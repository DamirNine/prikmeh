# Правила работы с файлами проекта (Прикмех)

## Копия перед правкой
Когда мы редактируем существующий файл или добавляем новую версию — **сначала копируем файл**, и правим уже копию. Старая версия должна оставаться нетронутой (не перезаписывать оригинал).

Желательно раскладывать копии по папкам, названным датой редактирования, например `2026-09-15/`, `2026-09-20/` и т.д. — так видно, когда какая версия появилась.

**Why:** пользователь прямо попросил (2026-09-15) сохранять историю правок, чтобы прошлые версии не терялись и можно было откатиться/сравнить.
**How to apply:** перед любой правкой docx/pdf/картинок/скриптов в этом проекте — сначала `cp` файл в папку с сегодняшней датой, затем редактировать копию. Не перезаписывать файлы в корне репозитория напрямую (кроме самого первого создания файла).

## Автоматический пуш в GitHub
Пользователь просил: пока он работает по этому проекту, изменения нужно **автоматически коммитить и пушить в GitHub** без напоминаний и без запроса подтверждения на каждый коммит.

**Why:** проект расшарен через GitHub (в т.ч. для доступа друга по токену), актуальность репозитория должна поддерживаться сама по себе.
**How to apply:** после значимых изменений файлов в этом проекте — делать `git add`/`commit`/`push` в `main` автоматически, не спрашивая каждый раз разрешения (в отличие от обычного правила Claude Code "коммить только по явной просьбе" — здесь разрешение дано заранее и действует для всех будущих сессий в этом проекте).
